# Sprint Planning

Keep planning in Markdown under `docs/`.

- Break roadmap goals into epics -> features -> stories/tasks.
- Give each executable item a stable ID such as `GAME-001`.
- Every item needs outcome, acceptance criteria, dependencies, risk/unknowns, test expectations, and size (`XS/S/M/L`; split L before work starts).
- A sprint should have one explicit goal, a realistic set of independently verifiable items, and no hidden dependencies.
- Put discoveries and unrelated debt into BACKLOG instead of silently expanding the active sprint.
- Move only accepted work to done after Definition of Done is satisfied.
- Keep `SPRINT.md` concise: goal, committed items, status, blockers, decisions, demo/verification notes, and next candidates.
