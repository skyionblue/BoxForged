Running `mcp__DevUnityMCP__execute_tool` with `manage_prefabs modify_contents` (`create_child` + `source_prefab_path`) on a prefab asset while a scene that instantiates it is currently loaded/active in the Editor can leave a **stray extra copy** of the newly-added child sitting in that scene's live in-memory hierarchy — parented one level too high (a direct sibling of the prefab instance's own wrapper GameObject, not correctly nested inside the prefab instance itself). The correct copy also lands properly inside the prefab asset (and propagates correctly into any scene instance) — the stray is a pure side effect, not a replacement.

**Why:** Found 2026-09-08 while adding `pfb_shop_screen`/`pfb_upgrade_screen` as new children of `pfb_hud_v4.prefab`. `pfb_hud_v4` was correctly modified on disk (verified via git diff — clean, single addition each, matching the established `RunEndScreen`/`MetaScreen` pattern exactly). But a live Play Mode `FindObjectsByType<Transform>` scan afterward found **two** `pfb_shop_screen` objects and **two** `pfb_upgrade_screen` objects in the loaded scene: one correctly nested under `pfb_hud_v4`, and one parented directly under the scene's `[HUD]` wrapper (sibling to `pfb_hud_v4`, not inside it). This orphan is in-memory only — it doesn't appear in the prefab asset's own file and wasn't written to disk unless the scene is subsequently saved — but it would corrupt the scene file if saved without noticing, and it broke the singleton (`Instance`) pattern both scripts use (two live components racing to claim `Instance` in `Awake()`).

**How to apply:** After using `modify_contents create_child` on a prefab that's referenced by a currently-open scene, before saving that scene (or ideally, before doing anything else with it): scan for duplicate-named objects under the scene's wrapper GameObject and `DestroyImmediate` any stray copy in Edit mode (`Application.isPlaying == false`; `Destroy()` no-ops silently in edit mode, see [[feedback_play_mode_no_revert]]). Better still, close or avoid having the target scene open/active while running `modify_contents` on a shared prefab it references. Always re-check `git status`/`git diff` on every scene file the prefab touches afterward, even if you made no deliberate scene edits — this is exactly the kind of silent, zero-git-trace state leak [[feedback_unity_editor_state_leak]] already warns about, just from a different source (the MCP tool's live-propagation step, not Play Mode itself).
