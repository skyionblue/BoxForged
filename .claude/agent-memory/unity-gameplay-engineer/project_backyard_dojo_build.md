**Read `docs/v4/levels/World2/backyard-dojo/zone-layout-spec.md` §9 first** — it defines the authoritative Stage A/B/C/D/E/F scope split this memory tracks against. Read `docs/adr/0005-world2-single-continuous-scene.md` for the architecture contract (three in-scene `RoomManager` zones, no scene loads, `ZoneDirector` reused from World 1).

**Stage A — DONE, 2026-09-01, `docs/BACKLOG.md` B115 has the full writeup.** Built entirely in Edit Mode via `execute_code` (no Play Mode touched this pass — the documented Play-Mode-scene-leak risk, see [[feedback_play_mode_no_revert]], does not apply to this pass). Ground resized (21×61m), `RoomTrigger_Zone1`/`_Zone2` repositioned/resized to spec, `RoomGate_Zone0`/`_Zone1` added (Collider+NavMeshObstacle+NavMeshModifier, mirroring World 1's exact pattern — no visual mesh, the stockade provides the visible chokepoint), full stockade perimeter (45 BD-01 placeholder cube modules incl. a 16-gon ring for zone 2), all three zones' prop dressing from the 8 existing dojo ENV prefabs, `RoomData_Backyard_Dojo_Zone0` fully populated (5 spawns, `maxConcurrentEnemies=4`), `WeaponDropTableSO_Backyard_Dojo` workbenches+cardboard piles populated, lighting retuned (jade-white key, flat cool green-grey ambient). `PlayerController` scene-instance override set (`_arenaCenter (0,0,26.5)`, `_arenaBoundaryRadius 30`).

**Validation run and passed, early per the spec's own instruction:** Edit-mode `NavMeshSurface.BuildNavMesh()` + `Physics` queries (not Play Mode) for: NavMesh bake (571 verts w/ gates closed), `ValidateCameraClearance`-equivalent raycast sweep (bucketed per zone — zone0 21.2%, zone1 28.8%, **zone2 57.7%** "behind" violations, far above World 1's 8% and the spec's own "small cluster" expectation, see B115 for why), gate-bypass flood-fill (three-configuration control per ADR-0005 §6.3, all three passed after fixing two real bugs found along the way — see below), and `NavMesh.CalculatePath` reachability for zone0's spawns/workbench/cardboard (all `PathComplete`) plus zone1/zone2 items checked from their own zone's interior (all `PathComplete` **except the engawa, which is `PathPartial`** — flagged, not fixed, see B115).

**Three real bugs found and fixed during this pass — read [[feedback_wall_tiling_yaw_axis_mismatch]] and [[feedback_baked_transform_child_collider]] before touching this scene again:**
1. A 90°-axis-swap in the wall-tiling helper's yaw/scale convention left every non-axis-aligned wall segment (chokepoint returns, the whole 16-gon ring) thin-side-on — caught by the flood-fill, all 45 modules rebuilt.
2. The cherry tree's trunk `CapsuleCollider` (added as a child, since the source prefab ships with zero colliders) and the six zone-2 court-dressing props' `NavMeshObstacle` center/size (computed via naive world-space subtraction) both inherited/ignored the dojo ENV prefabs' baked 270°X rotation (and the tree's additional 100× scale) — both fixed.
3. `pfb_env_bld_shedwithcrate` defaults to an east-west long axis (spec requires north-south, load-bearing for the post-boss engawa sightline) and `pfb_koi_pond_basin` defaults to ~1.9×1.9m against a 6.0×5.0m spec target — both fixed (shed +90° world yaw, pond non-uniform rescale to `(3.175,1,2.66)`).

**Open findings, not resolved this pass (all in B115, not silently decided):** no `WeaponObjectSO` wrapper exists for Bo Staff/Katana/Shurikens (only equipped `WeaponData` + pickup-visual prefabs exist; the wrapper needs per-character grip tuning, which [[feedback_weapon_grip_tuning_approach]] flags as a previously-failed agent-automation path awaiting a different approach) — `WeaponDropTableSO_Backyard_Dojo.scatteredObjects` is empty, workbenches/cardboard piles are not. The engawa's 0.35m step doesn't auto-connect on the baked NavMesh (project's actual `agentClimb=0.4`, not the spec-assumed 0.75) — needs `technical-director` input, cross-cutting NavMesh setting. The shed's overall footprint measures ~2× the spec's assumed dimensions even after the rotation fix — flagged for `art-director`/`asset-engineer`.

**Deliberately NOT built (Stage A's own scope boundary, see spec §9):** the `ZoneDirector` instance / `_clearOnBossZone` wiring for the six zone-2 court props (they exist and are pre-wired with NavMeshObstacle/Modifier pairs, just not connected to a director yet — Stage B, blocked on nothing now since the `WildWestCityZoneDirector→ZoneDirector` rename was already verified intact this session before Stage A began); the Skeptic beat (chair/Skeptic instance/trigger script, §3.5); the 3s Assembly Beat delay mechanism (§1.5); zone-0 intro camera (§1.4, owner call); BD-01…BD-07 real art (Stage C, blocked on the texture-import-policy being enabled); zone1/zone2 enemy `RoomData` spawn arrays (Stage D, blocked on `CraneDuelistAI`/Leaf-Pile-Lurker AI/`EnemyStats` not existing yet — authoring these now would throw runtime errors per `RoomManager`'s own guard); the Grasscutter boss itself (Stage E).
