Two confirmed gotchas when using Unity MCP tools to test something in Play Mode (found 2026-08-20 while verifying the B63 Lasso per-weapon grip fix — see [[project_weapon_grip_socket]]):

**1. `execute_code` calls made *while* Play Mode is running are unreliable — they can silently end Play Mode.** One read-only `execute_code` call (just enumerating `Canvas` objects) ended Play Mode partway through this session; it was only caught because `manage_scene`'s `get_active` action showed `rootCount` had dropped back to the edit-mode count (edit mode had 9 root objects in this project's `CulDeSac_Room1_v2`; Play Mode inflated it to 13). A different, much larger single `execute_code` call in the same session — that did all of one character's model-swap + weapon re-attach + wrote its own screenshot PNG to disk synchronously — completed fine, with Play Mode still running by the time the call returned, and only ended sometime after.

**How to apply:** don't trust Play Mode to still be running after any `execute_code` call — check immediately via `manage_scene get_active`'s `rootCount` (compare against a known edit-mode baseline for that scene) rather than assuming. Prefer doing the *minimum* necessary inside any one `execute_code` call while Play Mode is live (find objects, mutate state, call the one method needed), and prefer non-code MCP tools (`manage_camera`, `manage_gameobject`, `manage_components`) for anything achievable without compiling code, since those did not exhibit this problem. If a call needs to both mutate live state *and* produce visual proof, do the capture synchronously inside the same `execute_code` call (see gotcha 2 for why not to just call a screenshot API from C#) rather than relying on a second, separate tool call afterward.

**2. Manually rendering a camera from `execute_code` (`camera.Render()` + `RenderTexture` + `ReadPixels`) does not work under URP.** It produces a perfectly flat frame of the camera's own `Camera.backgroundColor` (`clearFlags = SolidColor`) instead of the actual scene — because a raw `Camera.Render()` call bypasses Unity's Scriptable Render Pipeline (`ScriptableRenderContext`) that URP (this project's pipeline) requires; it doesn't error, it just silently produces a blank/background-color frame, which is a confusing false negative (looks like "nothing is rendering" or "everything is hidden behind a screen," not like "wrong render call").

**How to apply:** always use `manage_camera`'s own `screenshot` action for Play Mode visual verification in this project — it renders correctly through URP. Its `view_target`/`view_position` parameters give a positioned close-up (e.g. for verifying a small prop like a held weapon) without needing custom render code, and plain `screenshot` (no camera specified) uses the real gameplay camera/Cinemachine rig. If a first attempt at a positioned close-up frames badly (e.g. character mid-animation or physically displaced by something in the scene), just retry with a different `view_position` offset rather than assuming the underlying fix is wrong — camera framing and grip correctness are separate questions.
